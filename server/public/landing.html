The Problem & Solution

ML deserves a real language.

The Problem
Python is not enough

Python was never designed for systems-level ML. Its dynamic typing, GIL, and interpreter overhead force engineers to write performance-critical code in C++ extensions, losing type safety and debuggability.

  • No static types → runtime shape errors
  • Slow interpreter → C++ extensions required
  • GIL → true parallelism blocked
  • No native tensor syntax → verbose boilerplate
  • Framework fragmentation across PyTorch/TF/JAX
The Solution
Nova — ML-first language

Nova is a statically-typed, compiled language where tensors are first-class citizens. Autograd, CUDA dispatch, and the full ML stdlib are built into the compiler, not bolted on as a framework.

  • Static types → shape errors at compile time
  • IR compilation → 500M instructions/sec
  • Native tensor syntax → zero boilerplate
  • Tape-based autograd → automatic differentiation
  • CUDA FFI → transparent GPU dispatch

Compiler Pipeline

From source to execution.

01
LEXER

Tokenizes Nova source. Keywords, operators, string/float literals, identifiers.

02
IMPORT

Preprocessor inlines stdlib files. Resolves NOVA_HOME for package imports.

03
PARSER

Recursive descent. Builds IR linked list. Classes, structs, functions.

04
IR GEN

Emits typed IR nodes: ASSIGN, CJMP, CALL, TENSOR_CALL, ARRAY_READ/WRITE.

05
OPTIMIZE

6-pass optimizer reduces node count, eliminates dead code, hoists invariants.

06
EXECUTE

IR interpreter with tensor heap, grad tape, and optional CUDA dispatch.
